版本：V2.1 RC2  
状态：增强方案  
目标：提升SQD真实链数据下载稳定性，不修改现有核心架构

---

当前系统已经完成：

- Provider Adapter
- Provider Router
- Checkpoint
- Dataset Registry
- Parquet Data Lake
- DuckDB分析

真实测试：

```
BSC Mainnet

↓

SQD StreamTraces

↓

122,892 transactions

↓

Parquet

↓

```

链路已经验证可用。

- SQD DNS偶发异常
- HTTP 503限流
- 网络连接失败
- 长任务中断风险

因此需要增加：

> SQD Download Reliability Layer

---

# 4. Retry机制

## 重试范围

允许重试：

- DNS失败
- Timeout
- Connection reset
- HTTP 503
- HTTP 429


禁止重试：

- HTTP 400
- 参数错误
- Schema错误

---

# 5. Backoff策略

采用指数退避：

```
第一次失败

等待2秒


第二次

等待5秒


第三次

等待15秒


第四次

等待30秒


第五次

等待60秒
```

最大：

```
5次
```

---

# 6. Rate Limit控制

问题：

公共SQD不适合无限并发。


增加：

```
SQD Worker Pool
```

默认：

```
8 workers
```

异常：

```
503增加

↓

降低到4 workers


继续失败

↓

降低到1 worker
```

恢复：

逐步增加。

---

# 7. Circuit Breaker

状态：

```
Healthy

↓

Degraded

↓

Open

↓

Half Open

↓

Recovery
```

---

规则：

连续：

```
5次失败
```

进入：

```
Open
```

等待：

```
60秒
```

测试：

一次请求。

成功：

恢复。

失败：

继续等待。

---

# 8. Chunk级恢复

禁止：

```
SQD失败

↓

整个Job失败
```


采用：

```
Chunk状态:

PENDING

DOWNLOADING

SUCCESS

RETRY

FAILED
```

---

示例：

|Chunk|状态|
|-|-|
|001|SUCCESS|
|002|SUCCESS|
|003|RETRY|
|004|SUCCESS|

只恢复：

003。

---

# 9. HTTP Client优化

要求：

连接复用。

配置：

```go
http.Transport{
 MaxIdleConns:100,
 IdleConnTimeout:90*time.Second,
}
```

避免：

- TCP重复建立
- DNS频繁解析
- 连接耗尽
