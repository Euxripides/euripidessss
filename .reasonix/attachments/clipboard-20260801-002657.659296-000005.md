# V2.1 RC2 Adaptive Start Block Resolver 智能起始区块算法方案

## 1. 背景

当前 resolveMinFirstSeen 算法：

所有地址取 first_seen_block 最小值作为统一下载起点。

优点：
- 不漏数据

缺点：
- 单个早期地址可能导致全量扫描范围扩大
- 增加 SQD 请求量和下载成本


## 2. 设计目标

实现：

- 0 数据遗漏
- 减少无效区块扫描
- 保持 Chunk Queue 兼容
- 不改变后续 Parquet / DuckDB / Analytics 链路


## 3. Adaptive Start Resolver

流程：

地址集合
→ 生命周期分析
→ 时间分布分析
→ 地址分组
→ 生成多个下载任务


## 4. 地址生命周期

每个地址维护：

- first_seen_block
- last_seen_block
- activity_count


## 5. 分级策略

### 小规模

地址数量 < 1000：

继续使用：

min(first_seen_block)


### 大规模

地址数量 >= 1000：

根据 first_seen_block 时间分布进行分组。


## 6. 时间分桶

示例：

地址:

A 8123456

B 9500000

C 10200000


生成：

Group1:
8123456 起


Group2:
9500000 起


Group3:
10200000 起


分别生成 Chunk 下载任务。


## 7. 孤立早期地址处理

如果：

9999 个地址集中在近期

1 个地址非常早


拆分：

legacy_group

normal_group


避免单个地址拖慢整体任务。


## 8. 新任务模型

旧：

Address List
→ Start Block
→ Chunk


新：

Address List
→ Address Groups
→ Start Blocks
→ Chunk Tasks
→ Dataset Merge


## 9. 系统集成

兼容：

- Dataset Registry
- Chunk Scheduler
- Checkpoint
- SQD Reliability Layer


不修改：

- Parser
- Parquet Writer
- DuckDB
- Analytics
