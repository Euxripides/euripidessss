# 地址关系图 V2.0 UI 偏差整改方案

> 依据文档：《加密货币交互式资金流向图技术设计与实施指南》  
> 整改目标：保留已完成的数据、BFS、统计、资产和安全能力，仅重构前端 UI，使页面严格符合文档第 5、10、11、12、13、18、19、22 节定义的暗色调查工作台布局与视觉验收标准。  
> 目标仓库：`E:\codex\etl`

---

## 1. 结论

当前开发结果没有按设计文档完成 UI。

开发实现主要完成了：

- 聚焦搜索
- 方向和深度筛选
- BFS 子图
- DuckDB 统计
- 实时资产
- 快照和 Investigation Agent 联动

但页面结构和视觉表现与文档明确要求严重不符。

这不是“风格略有差异”，而是以下关键要求未落实：

1. 文档要求全屏暗色调查工作台，开发结果是白色后台卡片页面。
2. 文档要求顶部一体化工具栏，开发结果保留了普通页面标题和 Card Header。
3. 文档要求右侧常驻地址 Inspector，开发结果没有实现目标结构。
4. 文档要求画布作为页面主体，开发结果把 ReactFlow 放入普通白色卡片。
5. 文档要求完整地址矩形节点、关系语义色和资金流动画，开发结果更接近默认 ReactFlow 节点。
6. 文档要求底部图例、聚焦状态和退出聚焦操作，开发结果布局不一致。
7. 文档明确给出背景、面板、文字、选中、上游、下游和交易所颜色值，但开发结果未执行。
8. 文档要求节点宽 390px、高 64px，并显示完整地址，开发结果节点尺寸和信息密度不符合。
9. 文档要求 1440×900 基准布局，开发结果没有按该基准验收。
10. 文档要求视觉验收与浏览器交互测试，最终交付只验证了功能和构建，没有证明 UI 与目标一致。

因此，V2.0 的“全部检查通过”只能代表：

```text
功能实现通过
```

不能代表：

```text
设计文档完整交付通过
```

## 2. 文档中的明确 UI 要求

### 2.1 页面结构

设计文档要求：

```text
┌──────────────────────────────────────────────────────────────┐
│ 品牌 │ 完整地址/哈希搜索 │ 方向 │ 深度 │ 操作              │
├──────────────────────────────────────────────┬───────────────┤
│                                              │ 地址详情       │
│                                              │ 概览统计       │
│               ReactFlow 画布                  │ 相邻地址       │
│                                              │ 交易记录       │
│                                              │ 证据边界       │
├──────────────────────────────────────────────┤               │
│ 图例                             退出聚焦      │               │
└──────────────────────────────────────────────┴───────────────┘
```

当前开发结果：

```text
页面标题
说明文字
白色 Card
Card Header
ReactFlow
```

两者属于不同页面架构。

### 2.2 颜色要求

必须使用：

```text
页面背景      #06111e
画布背景      #071522
面板背景      #0a1725
面板边框      #19354e
主文字        #edf8ff
次文字        #7f9db5

上游来源      #3f97ff
下游去向      #f59e32
交易所标记    #d7b34d
非聚焦关系    #3a536c
危险异常      #ef5b67
```

当前白色页面不符合该要求。

### 2.3 画布要求

必须：

- 全屏或接近全屏占据主要区域
- 暗色点阵背景
- 不使用外层普通 Card 包裹
- 右侧 Inspector 与画布同级
- 底部图例常驻
- 左下角缩放控制器
- 画布右上显示当前节点数和关系数

### 2.4 节点要求

必须：

```text
宽 390px
高 64px
圆角 9px
完整地址
角色/标签
选中状态
关系语义色
```

不得使用缩略地址或接近默认 ReactFlow 的小节点。

## 9. 节点视觉整改

### 9.1 中心节点

- 青色边框
- 青色状态点
- 发光效果
- 完整地址
- 角色
- “已选择”状态

### 9.2 上游节点

- 蓝色边框或关系标识
- 标签“上游来源”

### 9.3 下游节点

- 橙色边框或关系标识
- 标签“下游去向”

### 9.4 交易所节点

- 金色边框
- 标签写作“Binance 公开标记地址”
- 不得直接写“充值地址”或“归集地址”，除非有调证证据

### 9.5 尺寸

```css
width: 390px;
height: 64px;
border-radius: 9px;
```

实时资产加载不得改变节点尺寸。

## 12. 验收方法

### 12.1 必须进行截图对比

基准分辨率：

```text
1440×900
1920×1080
```

至少比较：

- 页面整体结构
- 顶栏高度
- Inspector 宽度
- Canvas 占比
- 节点尺寸
- 节点颜色
- 边颜色
- 图例位置
- 退出聚焦位置

### 12.2 视觉验收不能只靠测试通过

以下命令通过不能替代 UI 验收：

```text
npm run build
tsc
go test
security_review
```

必须增加：

```text
visual review
```

### 12.3 Playwright 截图

新增：

```text
graph-workspace-global.png
graph-workspace-focus.png
graph-workspace-inspector.png
graph-workspace-mobile.png
```

测试：

- 全局模式
- 聚焦模式
- Inspector
- 实时资产加载
- 资产失败状态
- 移动端 Drawer

### 12.4 验收结论

只有同时满足：

```text
功能测试通过
+
安全测试通过
+
视觉截图通过
```

才允许标记为最终交付完成。

## 14. Codex 强制规则

1. 本轮不修改 BFS、DuckDB、AssetService 和安全逻辑。
2. 不新增图形库。
3. 不保留白色 Card 作为主容器。
4. 不使用普通下拉框替代方向和深度分段按钮。
5. 不允许只改颜色而不改页面结构。
6. 必须按文档色值实现。
7. 必须按 390×64 节点实现。
8. 必须实现右侧常驻 Inspector。
9. 必须实现底部图例和退出聚焦。
10. 必须提交截图作为交付证据。
11. 未通过截图对比不得写“最终交付完成”。
12. 现有功能必须全部回归通过。

## 15. 完成定义

全部满足才算整改完成：

- 页面是全屏暗色调查工作台。
- 不再显示普通后台式大标题和白色 Card。
- 顶部工具栏与目标结构一致。
- Canvas 是页面主体。
- Inspector 常驻右侧。
- 节点和边符合文档视觉规范。
- 完整地址可读。
- 底部图例和退出聚焦存在。
- 全局和聚焦模式视觉正确。
- 统计、资产、交易和 Evidence 能在 Inspector 中使用。
- 1440×900 截图与目标页面结构一致。
- 功能、安全、构建和视觉验收全部通过。
