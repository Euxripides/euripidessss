# 地址导入与跨功能复用——用户级真实端到端测试流程

> 文档版本：1.0  
> 编写日期：2026-08-15  
> 项目：`E:\codex\etl`  
> 默认访问地址：`http://127.0.0.1:8000`  
> 主执行方式：真实浏览器、真实页面、真实服务、真实文件、真实任务、真实结果  
> 补充用例目录：`docs/ADDRESS_LIBRARY_FUNCTIONAL_TEST_CASES.md`

## 1. 测试目标

本流程模拟一名真实调查人员从第一次打开系统开始，完成地址文件导入、地址下载、结果查看、跨页面分析、资金追踪、风险筛查、刷新恢复、服务重启恢复、导出和异常恢复的完整工作。

本流程不是接口巡检，也不是把多个页面分别打开一次。测试必须形成连续的用户旅程：前一步产生的地址、任务、状态和结果，必须在后续页面继续使用并保持一致。

最终需要回答：

1. 普通用户是否能在没有调用开发接口的情况下完成全部操作？
2. 用户上传的地址是否真正持久化，而不是只停留在当前页面内存？
3. 地址是否能在 Smart Download、全局搜索、Explorer、地址画像、风险分析和资金追踪之间连续复用？
4. 下载、失败、部分完成、认证和可分析等状态是否与真实数据一致？
5. 用户刷新页面、关闭浏览器、重新打开系统或服务重启后，工作结果是否仍然存在？
6. 页面显示的交易、统计、风险、节点、关系和导出文件是否能够由真实数据核对？
7. 发生错误时，用户是否得到可理解的反馈并能继续操作？

## 2. 用户级真实测试的硬性规则

### 2.1 正常流程只能通过页面操作

以下动作必须通过浏览器完成：

- 进入功能页面。
- 选择网络。
- 上传 TXT、CSV、XLSX 文件。
- 清除文件导入结果。
- 从地址资产库载入地址。
- 填写或粘贴地址。
- 发起预检。
- 创建下载批次。
- 查看任务中心。
- 暂停、恢复、取消任务。
- 查看结果数据。
- 使用全局搜索。
- 打开 Explorer 地址详情。
- 翻页、筛选、展开详情和复制数据。
- 打开地址画像和风险分析。
- 在资金追踪中搜索地址、切换方向/深度、点击节点/边和使用 Inspector。
- 保存快照、加入调查或导出结果。
- 刷新页面、后退、前进和重新打开浏览器。

禁止通过 `POST /api/...`、直接写 SQLite、直接写 ClickHouse、修改任务 JSON 或修改浏览器 Local Storage 代替这些用户操作。

### 2.2 API 和数据库只能用于事后核证

用户完成页面操作后，测试 Agent 可以只读检查：

- 浏览器 Network 中页面实际发出的请求和响应。
- 地址库查询结果。
- Smart Download 批次、地址任务和结果状态。
- 控制库中的地址资产、任务和导入次数。
- ClickHouse `address_activity` 的明细和聚合行。
- 产出的 CSV、XLSX、Parquet、JSON 或 ZIP 文件。

只读核证不能替代 UI 操作，也不能以 HTTP 200 单独判定成功。

### 2.3 必须使用真实服务和真实数据链路

主流程不得使用模拟后端响应。必须连接当前项目真实服务、真实控制库和当前配置的数据平面。

故障恢复流程允许使用浏览器请求拦截模拟网络超时或 500，但必须单独标记为“受控故障注入”，不得与主流程的真实成功证据混合。

### 2.4 必须保留用户连续上下文

同一个主流程使用同一个浏览器 Context，保留：

- Cookie。
- Session Storage。
- Local Storage。
- 当前页面状态。
- 浏览器前进/后退历史。

只有专门验证“新用户/新浏览器”时才新建无痕 Context。

### 2.5 不允许的测试捷径

以下情况不能判定通过：

- 只调用接口，没有点击页面。
- 只证明按钮存在，没有点击。
- 只证明请求返回 200，没有核对页面结果。
- 只证明任务显示 COMPLETED，没有检查结果文件和数据行。
- 只证明地址出现在下拉框，没有选择并进入后续功能。
- 只截取静态页面，没有验证交互后的状态变化。
- 只运行构建、单元测试或 Playwright 脚本退出码。
- 用测试脚本直接修改 React 状态、Local Storage 或数据库制造成功状态。
- 将 SKIPPED、按钮未找到、外部条件缺失记录成 PASS。

## 3. 测试角色

### 3.1 主角色：资金调查人员

模拟一名不使用开发工具的业务用户：

- 知道要调查哪些地址。
- 会准备 TXT、CSV 或 XLSX 文件。
- 不了解 API 和数据库结构。
- 依赖页面提示判断下一步操作。
- 需要从导入一直完成到分析和导出。

### 3.2 辅助角色：复核人员

使用第二个浏览器 Context：

- 不重复导入原文件。
- 通过地址资产库搜索主用户导入的地址。
- 复核地址状态、Explorer 数据和资金追踪结果。
- 验证跨浏览器 Context 的持久化，而不是当前页面内存共享。

### 3.3 移动端用户

使用 390×844 viewport 完成关键操作：

- 全局搜索地址。
- 打开 Explorer 地址页。
- 打开风险分析。
- 打开资金追踪并选择节点。
- 查看空状态和错误提示。

## 4. 浏览器与环境要求

### 4.1 浏览器选择

1. 优先使用 Browser 插件及 browser skill。
2. Browser 可用时必须记录会话名、页面 URL、DOM、Console、Network 和截图。
3. Browser 不可用时使用 Playwright + 系统 Chrome，并在报告写明：

```text
Browser plugin not available; regular Playwright fallback used.
```

4. 浏览器必须显示真实页面，禁止仅使用 request/context API 完成业务步骤。

### 4.2 Viewport

至少执行：

- 桌面：1440×900。
- 大屏：1920×1080。
- 移动端：390×844。

主用户旅程使用桌面尺寸；移动端单独复跑关键步骤。

### 4.3 环境独占

以下流程执行时不得有其他 Agent 同时写入同一环境：

- 导入文件。
- 创建/启动/暂停/恢复/取消下载任务。
- 服务重启。
- 容量测试。
- 故障注入。
- 导出和结果文件核对。

每轮使用唯一 RUN_ID：

```text
YYYYMMDD-UAT-序号
示例：20260815-UAT-01
```

### 4.4 启动前检查

测试 Agent 可以通过终端启动项目，但业务测试必须从浏览器首页开始。

启动前记录：

- Git commit 和工作区状态。
- 服务 PID。
- 浏览器版本。
- 当前时间及时区。
- 控制库路径。
- 当前数据平面模式。
- 当前地址库各状态数量。
- 测试输出目录。

健康接口只用于确认环境能够开始测试，不属于功能 PASS 证据。

## 5. 测试数据包

### 5.1 真实状态地址

每轮开始时从当前地址资产库动态选择：

| 代号 | 要求 | 用途 |
|---|---|---|
| `A_AVAILABLE` | 有真实活动行 | Explorer、画像、风险、资金图 |
| `A_AVAILABLE_HIGH` | 活动量较高 | 分页、性能、图聚合 |
| `A_CERTIFIED` | 已认证但无活动行 | 数据边界 |
| `A_PARTIAL` | 部分完成 | 状态边界 |
| `A_FAILED` | 下载失败且无活动行 | 错误/空状态 |
| `A_NEW` | 当前地址库不存在的合法地址 | 新用户导入 |
| `A_DUPLICATE` | 文件中重复出现的合法地址 | 去重 |
| `A_CROSS_CHAIN` | 同时导入 BSC 和 Ethereum | 跨链同地址 |

如果某种状态当前不存在，不允许伪造为该状态。应先通过真实任务形成该状态，或把对应旅程记为 BLOCKED 并说明缺少什么。

### 5.2 用户风格文件

测试文件必须像真实用户文件，而不是只含一个最小测试单元。

#### USER-ADDRESSES.txt

包含：

- 文件标题或说明文字。
- 5–20 个合法地址。
- 大小写混合地址。
- 重复地址。
- 空行。
- 地址前后的空格。
- 1–2 个非法地址。
- 一行备注文本。

#### USER-ADDRESSES.csv

至少包含：

```text
序号,address,chain,案件编号,备注
```

其中：

- 地址列不是第一列。
- 包含重复地址。
- 包含空地址。
- 包含另一个非地址的 `hash` 或 `备注` 列。
- UTF-8 BOM 场景至少执行一次。

#### USER-ADDRESSES.xlsx

至少包含三个 Sheet：

1. `使用说明`：无地址列。
2. `BSC地址`：合法、重复、非法地址混合。
3. `复核名单`：含与第二个 Sheet 重复和新增的地址。

这份文件用于模拟真实办案表格，必须验证系统扫描全部工作表。

#### USER-BROKEN.xlsx

损坏或伪装扩展名文件，用于验证用户错误反馈。

### 5.3 文件来源和校验

执行前记录每个文件：

- 文件名。
- 文件大小。
- SHA-256。
- Sheet 名。
- 原始地址总数。
- 合法地址数。
- 唯一合法地址数。
- 非法/空行数。
- 按链预期数量。

## 6. 证据规范

### 6.1 每一步必须记录

| 证据 | 内容 |
|---|---|
| 操作前截图 | 用户点击前页面状态 |
| 操作后截图 | 页面状态发生变化后的结果 |
| 操作记录 | 点击、输入、选择、上传、等待、刷新等真实动作 |
| URL/标题 | 当前页面身份 |
| DOM 摘要 | 关键可见文本、按钮状态、表格行、图节点/边 |
| Network | 页面实际请求、状态、响应摘要、耗时 |
| Console | error/warn；无错误也记录 none |
| 数据核对 | 地址库、任务、ClickHouse、输出文件的只读核证 |
| 时间 | 操作起止时间和等待时长 |
| 结论 | PASS/FAIL/BLOCKED |

### 6.2 截图要求

- 截图必须包含能够识别页面和结果的区域。
- Toast 一闪而过时要在可见期间截图。
- 下拉残留、遮挡、重复项等问题必须截图下拉打开状态。
- 资金图必须截图画布节点、关系、计数徽章和 Inspector。
- 不能用接口 JSON 截图代替 UI 截图。

### 6.3 视频或 Trace

主用户旅程建议录制浏览器视频或 Playwright Trace。视频不能代替逐步断言，但可用于复现短暂状态、竞态和跳转问题。

## 7. 主用户完整旅程

主流程必须按 UJ-01 → UJ-12 的顺序执行。除非发生阻断错误，不得拆成互不关联的脚本并任意跳过中间状态。

## 8. UJ-01：首次打开系统与功能识别

### 用户目标

用户第一次打开系统，确认系统可用并找到地址导入入口。

### 用户操作

1. 新建浏览器 Context，不预设 Local Storage。
2. 输入 `http://127.0.0.1:8000`。
3. 等待首屏稳定，不主动刷新。
4. 确认应用标题、左侧导航和顶部全局搜索可见。
5. 使用鼠标逐项查看导航。
6. 点击“智能下载”。
7. 查看创建下载、任务中心、智能预取、结果数据四个页签。
8. 使用浏览器后退，再使用前进返回。
9. 刷新当前页一次。

### 用户级断言

- 首屏不是白屏或框架错误页。
- 导航名称可理解，不需要用户知道 URL。
- 点击导航后页面标题与功能一致。
- 后退/前进不会进入错误页面或丢失整个应用。
- 刷新后仍在可理解的功能位置。
- 无相关 Console Error、未处理 Promise 或失败资源。

### 证据

- 首页、Smart Download 和刷新后截图。
- URL/标题变化。
- Console/Network 基线。

## 9. UJ-02：通过真实文件导入地址

### 用户目标

用户拿到调查地址文件，希望上传后看到系统识别结果，并在刷新后继续使用。

### A. TXT 文件

1. 在创建下载页选择 BSC。
2. 点击“上传 CSV / XLSX / TXT”。
3. 在系统文件选择器选择 `USER-ADDRESSES.txt`。
4. 等待导入完成提示。
5. 阅读导入摘要，不直接进入下一步。
6. 核对识别总数、合法数、唯一数、重复数和非法数。
7. 检查文本中合法地址是否出现在最终任务地址区域。
8. 检查非法地址没有进入最终地址集合。
9. 截图摘要和最终地址。

### B. 清除临时选择并恢复

1. 点击“清除导入”。
2. 确认当前页面的临时摘要和地址输入被清空。
3. 刷新浏览器。
4. 再次进入创建下载页。
5. 点击“使用 BSC 地址资产库”。
6. 确认刚才导入的合法地址重新出现。

这一步必须证明“清除导入”只清除当前临时选择，不删除已经持久化的地址资产。

### C. CSV 文件

1. 再次点击上传按钮。
2. 选择 `USER-ADDRESSES.csv`。
3. 核对系统选择的是 `address` 列，而不是序号、hash、案件编号或备注列。
4. 核对重复地址没有生成重复任务地址。
5. 核对原文件中的案件备注没有被执行或渲染为 HTML。
6. 刷新后从地址资产库重新载入并核对集合。

### D. 多 Sheet XLSX

1. 上传 `USER-ADDRESSES.xlsx`。
2. 用户不应被要求手工删除“使用说明”Sheet。
3. 系统必须继续扫描 `BSC地址` 和 `复核名单`。
4. 核对两个有效 Sheet 的地址已合并。
5. 核对跨 Sheet 重复地址只出现一次。
6. 核对说明页文本没有被当成地址。
7. 刷新并从地址库恢复。

### E. 损坏文件

1. 上传 `USER-BROKEN.xlsx`。
2. 观察错误提示。
3. 关闭提示或重新选择文件。
4. 上传一个有效 TXT，确认用户可以恢复操作。

### 业务验收

- 所有导入均由文件选择器触发。
- 导入摘要与文件真实内容一致。
- 地址真正进入地址资产库。
- 刷新和清除临时结果后仍能恢复。
- 多 Sheet XLSX 必须完整扫描。
- 坏文件不会令页面白屏或使后续上传失效。
- 页面无重复地址、错链、旧摘要残留或 XSS。

## 10. UJ-03：从导入地址创建真实下载任务

### 用户目标

用户把已导入地址变成真实下载任务，并能理解预检和任务状态。

### 前置条件

- 使用隔离测试环境或得到允许执行外部下载任务。
- 选择一个可控区块范围，避免无边界全历史下载。
- 不直接调用创建批次 API。

### 用户操作

1. 在创建下载页选择 BSC。
2. 点击“使用 BSC 地址资产库”。
3. 从载入集合中保留 1–3 个本轮测试地址。
4. 选择资源档位、任务优先级、数据集和区块范围。
5. 点击“预检”。
6. 阅读预检结果：地址、链、范围、预计数据集、Provider 计划和预算提示。
7. 修改一次区块范围，重新预检，确认旧预检结果被替换。
8. 点击创建批次。
9. 等待成功反馈和批次编号。
10. 点击进入任务中心，而不是通过 URL 或 API 直接打开。

### 业务验收

- 预检地址集合与页面保留地址完全一致。
- 预检使用当前所选链，不继承之前的 Ethereum/BSC 选择。
- 修改参数后旧预检结果失效。
- 创建按钮的 loading、成功和失败状态清晰。
- 创建一次只产生一个批次，不因双击生成重复任务。
- 任务中心中的地址数量与创建页一致。

## 11. UJ-04：真实任务生命周期

### 用户目标

用户在任务中心观察任务从排队到完成，期间尝试暂停、恢复和取消。

### A. 正常完成任务

1. 在任务中心找到刚创建的批次。
2. 展开批次和地址任务详情。
3. 观察 `QUEUED/PLANNING/RUNNING` 等真实状态变化。
4. 等待进度、Provider、Range 和已下载数量更新。
5. 刷新页面，确认任务仍存在且状态没有回退到初始值。
6. 关闭浏览器标签页，重新打开系统并回到任务中心。
7. 继续等待任务进入最终状态。

### B. 暂停和恢复

1. 对专门的可暂停测试任务点击“暂停”。
2. 确认状态和用户反馈发生变化。
3. 等待一段时间，确认进度不再继续增长或页面明确说明当前阶段不能立即暂停。
4. 刷新页面确认暂停状态保持。
5. 点击“恢复”。
6. 确认任务从检查点继续，不从零重复下载已完成范围。

### C. 取消

1. 新建一个专门用于取消的小范围任务。
2. 在确认对话框点击取消操作。
3. 确认任务进入取消终态。
4. 刷新后状态保持。
5. 取消任务不得显示为 COMPLETED/CERTIFIED/AVAILABLE。

### 最终数据验收

任务显示完成不能单独 PASS。必须核对：

- 输出文件真实存在且非零字节。
- 文件可以打开和解析。
- 下载行数与结果页一致。
- 唯一键、重复数、缺口、预期/实际数量和 coverage 可解释。
- 地址、链、区块范围与任务一致。
- 必填交易字段非空。
- 认证状态与数据质量证据一致。
- ClickHouse 入仓行属于本任务地址和链。

## 12. UJ-05：结果数据与导出

### 用户目标

用户完成下载后在页面找到结果、筛选记录并导出。

### 用户操作

1. 从任务详情点击进入结果数据。
2. 确认页面默认展示刚完成任务或能够通过筛选找到它。
3. 按地址、链、数据集和状态筛选。

## 18. UJ-11：用户错误与恢复

### 18.1 非法地址

1. 用户停留在地址搜索或任务中心。
2. 临时将浏览器置为 offline。
3. 执行查询或刷新。
4. 确认显示网络错误，不显示旧结果为新结果。
5. 恢复 online。
6. 用户重新点击或刷新后功能恢复。

受控拦截地址建议请求：

- 下拉建议立即清空。
- 页面不崩溃。
- 输入框和其他功能仍可用。
- 恢复后再次聚焦可以重新查询。
- 注入的 500 必须在报告标为预期故障，不计入产品非预期 5xx。

## 23. 结果判定

### PASS

一个用户旅程只有在以下内容全部通过时才为 PASS：

- 用户能够完成所有必要点击和输入。
- 页面状态正确。
- 后续页面能够继续使用前一步结果。
- 刷新/恢复行为符合设计。
- 数据核对一致。
- 输出文件可用。
- 无非预期 Console/Network 错误。

### FAIL

以下任一情况直接 FAIL：

- 用户无法找到或完成操作。
- 地址、链、状态或任务串用。
- 页面显示成功但没有真实写入或文件。
- 任务完成但数据缺失、重复、错链或无法解析。
- 无数据被显示为低风险或完整覆盖。
- 资金图没有真实关系却显示分析结论。
- 刷新/重启后持久化对象丢失。
- 错误后页面无法恢复。
- 关键按钮未点击、未找到或跳过。

### BLOCKED

只有外部前置条件确实不存在时使用，例如：

- 未获准启动真实外部下载。
- 当前无可形成特定状态的数据源。
- 故障注入环境不可用。

必须写明阻断原因、已完成检查和解除阻断所需条件。

不能把 78 条接口/组件断言拼接起来，替代连续用户旅程。

## 27. 最终验收门槛

只有同时满足以下条件，产品验收才可以 PASS：

1. 主用户 UJ-01..UJ-12 全部执行；外部阻断项有明确批准的 BLOCKED 记录。
2. 用户通过 UI 完成导入、任务、结果、搜索、Explorer、画像、风险和资金追踪闭环。
3. 至少一个真实下载任务完整走过创建、运行、结果和入仓链路。
4. 至少一个任务实际执行暂停/恢复，另一个任务实际取消。
5. TXT、CSV、多 Sheet XLSX 和坏文件均通过真实文件选择器测试。
6. AVAILABLE、CERTIFIED、PARTIAL、FAILED 和新导入地址均完成用户级验证。
7. 风险分析无数据时显示数据不足，不显示低风险。
8. 资金追踪按方向显示真实关系，纯白背景无点阵，不误开智能补数。
9. 刷新、关闭浏览器、第二 Context 和服务重启后持久化对象仍存在。
10. 页面、控制面、ClickHouse 和输出文件能够相互核对。
11. 桌面、移动端和键盘关键路径无阻断。
12. 报告数字能够从原始证据逐条复算。

如果只完成接口检查、单元测试、构建或静态截图，本轮必须记为 PARTIAL，不能声明用户验收通过。
