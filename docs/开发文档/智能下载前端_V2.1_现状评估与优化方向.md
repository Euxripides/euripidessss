# 智能下载前端 V2.1 — 现状评估与下一阶段优化方向

## 0. 结论

当前前端已经完成了“智能下载”的基本骨架：

```text
创建下载
任务中心
结果数据
```

并且已经具备：

- 地址输入
- CSV/XLSX/TXT 上传
- 链选择
- Dataset 选择
- 全量 / 时间 / 区块范围
- Local Hit 开关
- 任务列表
- 结果列表
- 校验状态
- 结果表格
- 导出
- 地址画像 / 关系图 / 智能调查入口

下一阶段不建议再继续“加页面”，而应该把重点转到：

> **任务中心的可观测性 + 地址级任务控制 + 结果页的数据可读性 + 大批量任务性能 + 本地数据复用自动化。**

---

# 1. 当前 UI 已经做对的部分

## 1.1 信息架构已经基本正确

现在采用：

```text
创建下载
任务中心
结果数据
```

比之前把所有能力塞在一个 Parquet 页面合理很多。

这三个页签应该继续保留，不需要再拆更多一级页面。

---

# 1.2 创建页已经足够简洁

当前包含：

```text
地址
上传 CSV / XLSX / TXT
网络
数据类型
时间范围
开始智能下载
```

用户不需要选择：

```text
CSV / SQD / RPC / SQD Cloud
```

这是正确方向。

---

# 1.3 结果页已经开始形成“数据资产”概念

当前不是简单给用户一个文件，而是：

```text
已入库结果
↓
选择 Dataset
↓
表格查看
↓
导出
↓
进入地址画像 / 关系图 / 智能调查
```

这一点应该继续强化。

---

# 2. 当前最明显的问题

## 2.1 任务中心仍然是“Batch 列表”，不是“智能下载任务中心”

当前任务中心主要显示：

```text
任务ID
链
地址数
状态
数据集
操作
```

但用户真正关心的是：

```text
现在在下载哪个地址？
下载到多少？
使用什么 Provider？
当前速度多少？
还有多久？
是否正在切换 Provider？
是否正在校验？
哪个地址失败？
```

因此当前任务中心只能回答：

> “任务是什么状态”

还不能回答：

> “任务现在到底在干什么”

这是下一阶段最优先优化点。

| 0x72…998 | 校验中 | 94% | Logs | — | 18 MB/s | 392k | 00:34 | 详情 |

这张表应该成为任务中心的核心。

# 5. P0 优化三：Provider 切换必须可视化

系统最重要的能力之一就是：

```text
SQD
↓
RPC
↓

```

但目前前端看不出来。

应该显示：

```text

SQD

SQD → RPC

```

```text
SQD Cloud · L

```

# 6. P0 优化四：创建页增加 Discovery 反馈

当前点击：

```text
开始智能下载
```

后建议不要直接无反馈跳任务页。

增加一个短暂阶段：

```text
正在分析数据规模…
```

例如：

```text
地址数：12,093
数据类型：4

小任务        8,912
中型任务      2,181
大型任务        856
超大型任务      144

预计数据量：
≈ 182 GB
```

然后：

```text
系统将自动选择最合适的数据源
```

自动进入任务中心。

不要求用户确认。

# 7. 创建页布局优化

当前页面的问题不是功能少，而是“纵向过长、空白偏多”。

```text
┌─────────────┬───────────────┐

└─────────────┴───────────────┘

┌─────────────────────────────┐
```

底部：

```text

```

# 9. “本地已有数据直接复用”不建议做成普通 Checkbox

当前：

```text
□ 本地已有数据直接复用
```

更合理的是：

```text
系统自动复用本地已验证数据
```

默认始终启用。

原因：

用户没有必要主动选择：

> “我要不要重复下载已经存在的数据？”

正常情况下答案永远应该是：

```text
不重复下载
```

如果确实需要强制重新下载，应放到：

```text
高级设置
```

例如：

```text
□ 强制忽略本地缓存重新下载
```

默认关闭。

# 10. P0 优化五：结果页从“文件结果”升级为“调查数据浏览器”

# 10.1 Dataset 名称应该用户化



# 10.5 Direction 应该直接算出来


```text

```

这样分析资金流会快很多。

---

# 10.6 Amount 应该标准化

不要只显示：

```text

```

优先：

```text

```

并保留：


# 12. 结果列表优化

当前“已入库结果”列表存在一个问题：

同一地址可能出现：

```text

token_transfers
token_transfers
```

但区间不同。

建议改成：

```text
Address
↓
Dataset
↓
Coverage
```

例如：

```text

├─ 代币转账
│  Coverage: 114474200 → 114474299
│  Rows: 7
│  VALIDATED
│
└─ 当前余额
   Latest
   Rows: 1
```

不要让用户看到多个难以理解的“同地址同 Dataset 行”。

# 32. 最重要的下一步

从目前截图看，下一阶段最值得优先做的并不是继续修改“创建下载”页面。

最值得做的是：

```text
任务中心 V3
```

因为当前创建页已经基本够用，结果页也已经能展示数据。

真正缺的是：

> **让用户在任务执行过程中看得懂“系统现在在干什么”。**

所以推荐下一份实施文档正式命名：

```text
Smart Download Task Center V3
地址级实时任务中心与调度可观测性
```

其核心目标：

```text
每个地址
每个 Dataset
每个 Provider
每次切换
每次 Retry
每次 Validation
每个 Gap Repair
```

都能够在一个清晰、低噪声的任务中心里实时查看和控制。
