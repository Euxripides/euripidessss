# V2.1 RC2 DeepSeek驱动自主调查Agent设计方案

版本：V2.1 RC2

阶段：AI Driven Autonomous Investigation Agent

---

## 1. 背景

当前系统已经完成：

- 链上数据资产
- DuckDB分析引擎
- 地址画像
- 资金流分析
- 图谱分析
- 风险检测
- Investigation Loop闭环
- Task Queue
- Observation Engine
- Decision Engine
- 自动报告

当前限制：

- Planner主要依赖规则
- DEEP_ANALYSIS能力有限
- AI主要负责解释

目标：

引入DeepSeek，使系统具备：

```
理解调查目标
↓
制定调查策略
↓
提出分析假设
↓
指导下一步调查
↓
验证假设
↓
生成结论
```

---

## 2. 设计原则

AI不负责：

- 交易解析
- 金额计算
- 图计算
- 路径搜索
- 余额计算

AI负责：

- 调查规划
- 行为理解
- 假设生成
- 路径解释
- 报告总结

---

## 5. Planner Agent

职责：

根据当前调查状态生成策略。

输入：

- 目标地址
- 地址画像
- 资金路径
- 风险事件
- 实体信息
- 历史调查记录

输出：

结构化任务：

```json
{
"strategy":"trace_outgoing",
"tasks":[
 {
  "type":"PATH_TRACE",
  "priority":0.95
 }
]
}
```

## 7. Hypothesis Agent

增加调查假设能力。

例如：

发现：

```
A收到100万USDT

5分钟后

拆分20个地址
```

AI提出：

```
可能存在资金分层行为
```

生成验证任务：

- 检查共同控制
- 检查归集节点
- 检查交易所出口

---

## 8. DEEP_ANALYSIS Agent

流程：

```
触发条件

↓

AI分析

↓

生成假设

↓

执行验证

↓

确认或否定
```

所有结论必须经过数据验证。

---

## 9. AI Context Builder

禁止直接发送海量交易。

流程：

```
DuckDB

↓

Analytics Summary

↓

Context Builder

↓

DeepSeek
```

上下文包括：

- 地址摘要
- Top路径
- 风险事件
- 实体信息
- 调查历史

---

## 10. Prompt设计

采用多角色：

### Investigator

负责调查方向。

### AML Analyst

负责风险模式。

### Forensic Analyst

负责证据分析。

### Report Writer

负责报告生成。

## 11. AI输出约束

```json
"evidence":[
"tx_hash",
"block_number"
]
}
```
