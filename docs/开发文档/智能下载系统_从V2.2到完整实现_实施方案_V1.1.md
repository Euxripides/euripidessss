# 智能下载系统实现方案 V1.1
## 从 Smart Download Orchestrator V2.2 迁移到统一智能下载入口

> 目标：不重写现有下载器，在其上增加统一任务控制层，实现：
>
> - 单个/批量地址
> - CSV/XLSX 自动识别地址列
> - 每地址独立任务、进度、暂停、恢复、取消
> - 每个 Dataset 自动选择 CSV / SQD / RPC / SQD Cloud
> - Provider 可切换且不重复下载已完成数据
> - 断点续传
> - 缺口补洞
> - 下载完成自动校验、标准化、入 DuckDB、前端表格展示
> - 最终与地址画像、关系图、智能调查直接联动

# 2. 第一步：改任务模型

现有：

```text
Plan
└── PlanTask(dataset + chain + 地址组)
```

新模型：

```text
BatchJob
└── AddressJob
    └── DatasetJob
        └── RangeJob
```

## BatchJob

一次用户提交。

```go
type BatchJob struct {
    ID        string
    ChainKey  string
    ChainID   int64
    Status    BatchStatus

    AddressCount int
    DatasetTypes []DatasetType

    CreatedAt time.Time
    UpdatedAt time.Time
}
```

## AddressJob

每个地址独立。

```go
type AddressJob struct {
    ID       string
    BatchID  string
    Address  string
    ChainID  int64

    Range    RangeSpec
    Status   AddressStatus

    PauseRequested  bool
    CancelRequested bool

    Progress ProgressSnapshot
}
```

## DatasetJob

同一个地址不同 Dataset 可以使用不同 Provider。

```go
type DatasetJob struct {
    ID           string
    AddressJobID string
    Dataset      DatasetType

    Status       DatasetStatus
    CurrentProvider string

    EstimatedRows  uint64
    DownloadedRows uint64
    ValidatedRows  uint64

    RangeIDs []string
}
```

## RangeJob

Provider 切换和断点续传的最小单位。

```go
type RangeJob struct {
    ID           string
    DatasetJobID string

    FromBlock uint64
    ToBlock   uint64

    Provider string
    Status   RangeStatus

    RowsCommitted uint64
    Bytes         uint64
}
```

# 3. 地址组只作为网络优化，不再作为任务单位

原来 SQD 可能 100 地址一组：

```text
100 addresses → one SQD request
```

以后仍然可以这么请求。

但业务状态必须拆成：

```text
Address A → DatasetJob → Range
Address B → DatasetJob → Range
...
Address Z → DatasetJob → Range
```

Scheduler 可以把 100 个兼容 Range 临时合并成：

```text
ProviderRequestBatch
```

下载回来以后再按地址拆分写入。

这样才能做到：

```text
A 暂停
B/C/D 继续
```

# 4. 第二步：Universal Checkpoint V3

Provider page/cursor 不能作为主断点。

主断点必须是：

```text
哪些 Range 已经完成
哪些 Part 已经 commit
哪些 Range 为空
哪些 Range 还没完成
```

例如：

```json
{
  "version": 3,
  "dataset_job_id": "ds_xxx",
  "address": "0x...",
  "dataset": "token_transfers",
  "requested_range": {
    "from_block": 40000000,
    "to_block": 50000000
  },
  "completed_ranges": [
    [40000000, 40999999],
    [41000000, 41999999]
  ],
  "confirmed_empty_ranges": [],
  "pending_ranges": [
    [42000000, 42999999],
    [43000000, 43999999]
  ],
  "parts": [
    {
      "name": "part-000001.parquet",
      "sha256": "...",
      "rows": 25000
    }
  ],
  "provider_state": {
    "provider": "sqd",
    "cursor": "..."
  }
}
```

切换 Provider 时：

```text
保留 completed_ranges
保留 parts
清空或归档 provider_state
重新选择 Provider
从 pending range 继续
```

# 6. 第四步：Provider Adapter

所有现有下载器包成统一接口。

```go
type ProviderAdapter interface {
    Name() string

    Supports(req CapabilityRequest) bool

    Probe(
        ctx context.Context,
        req ProbeRequest,
    ) (ProbeResult, error)

    Execute(
        ctx context.Context,
        req RangeRequest,
        checkpoint ProviderCheckpoint,
    ) (ProviderResult, error)

    Health() ProviderHealth
}
```

适配：

```text
BrowserCSVAdapter
DirectAdapter
SQDAdapter
RPCAdapter
SQDCloudAdapter
```

重点：

Provider 不负责：

```text
任务最终状态
Checkpoint 主逻辑
最终文件 Schema
最终去重
```

Provider 只负责：

```text
把某个 Range 的原始数据拿回来
```

# 8. Probe 怎么做

不同 Provider 用不同低成本方法。

## CSV / 浏览器接口

如果目标网站/API 有：

```text
total
pagination count
last page
```

只请求第一页即可估算。

## SQD

使用：

```text
小窗口 sample
+
活跃度
+
block density
```

估算。

## RPC

使用：

```text
eth_getLogs 分段 probe
eth_getTransactionCount
first/last seen
```

注意 Probe 不应该完整扫描。

Probe 的目标只是：

```text
足够好地分类 S/M/L/XL
```

不是追求精确到 1 条。


# 12. Provider 切换怎么实现

这是最关键的。

假设：

```text
Range 1 完成
Range 2 完成
Range 3 SQD 下载中
```

SQD 连续 503：

```text
SQD
↓ retry
↓ retry
↓ circuit open
```

Executor：

```go
if shouldSwitchProvider(err) {
    state.MarkSwitching(rangeID)

    next := scheduler.SelectNextProvider(
        datasetJob,
        rangeJob,
        failedProviders,
    )

    state.RecordProviderSwitch(
        rangeID,
        current,
        next,
        reason,
    )

    rangeJob.Provider = next
    rangeJob.Status = READY
}
```

然后新 Provider 接着执行 Range 3。

**Range 1、2 不动。**

# 13. 当前 Range 已下载一半怎么办

有两种策略。

## Provider 可以精确定位

比如 block-based：

```text
Range 3:
42,000,000 - 42,049,999

已安全提交到：
42,022,500
```

新 Provider：

```text
42,022,501 - 42,049,999
```

## Provider 不能精确断点

重新跑整个 Range 3。

但最终：

```text
Canonical unique key
+
SHA / Part dedup
```

保证重复不会进入 final。

也就是说：

```text
最多重跑当前 Range
绝不重跑已完成 Range
```

# 18. 第九步：Pause / Resume / Cancel

## Pause

API：

```text
POST /api/smart-download/.../pause
```

不是直接 kill。

流程：

```text
PauseRequested = true
↓
不领取新 Range
↓
当前 Range 到安全 checkpoint
↓
flush
↓
save checkpoint
↓
PAUSED
```

## Resume

```text
重新检查 Provider Health
↓
可继续原 Provider
或重新调度
↓
未完成 Range → READY
```

## Cancel

```text
停止新 Range
↓
安全 flush
↓
保存 checkpoint
↓
CANCELED
```

保留数据，除非用户明确删除。

# 21. 第十一步：Validation Pipeline

下载结束后不要直接 COMPLETED。

流程：

```text
DOWNLOADED
↓
VALIDATING
```

## L1 File

```text
Parquet readable
Schema
SHA256
Footer
```

## L2 Record

```text
unique key
address format
hash format
block valid
```

## L3 Coverage

```text
requested_range
=
completed_ranges
+
confirmed_empty_ranges
```

如果：

```text
unknown_range != 0
```

不能 COMPLETED。

## L4 Provider Count

如果 Provider 能提供 count：

```text
expected == actual_unique
```

## L5 Gap Repair

缺：

```text
44,100,000 - 44,120,000
```

自动创建：

```text
Repair RangeJob
```

交给次优 Provider。

## L6 Cross Check

大地址抽样：

```text
随机 5~20 个 block windows
```

用第二 Provider 对比：

```text
count
tx hashes
log keys
```
